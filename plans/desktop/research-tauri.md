## 2. Rust to webview streaming

| Mechanism | Use for | Why |
|---|---|---|
| command (`invoke`) | request/response: start turn, cancel, load session, open report | typed, awaits a result |
| `tauri::ipc::Channel<T>` | token deltas, step progress | docs: "designed to be fast and deliver ordered data"; used internally for download progress and child process output; each message carries an index and JS reorders [V] |
| events (`app.emit`) | rare app-wide notices (e.g. "data refreshed" to all windows) | docs: "not designed for low latency or high throughput"; JSON only, untyped, not covered by capabilities [V] |

Decision: one `Channel<TurnEvent>` per turn, passed as a command argument.

- `Channel<T>` is `Clone`, and `Send + Sync` when `T` is [V docs.rs 2.12.5], so it can move into a std thread and keep sending after the command has returned. Dropping the last clone tells JS the stream ended [V].
- Sync commands run on the main thread [M]: never block in them. Do not call blocking reqwest inside an `async` command either (tokio context panic on runtime drop) [M]. Spawn a std thread - which is exactly core's existing model.
- `send` returns `Err` once the webview is gone/reloaded: treat as cancel.
- Deltas at more than ~60/s: coalesce in the forwarder (flush every ~16-30 ms) rather than one IPC message per token [M - general guidance, no official numbers].

```rust
#[derive(Clone, serde::Serialize)]
#[serde(tag = "type", rename_all = "camelCase")]
enum TurnEvent {
    Delta { text: String },
    Step { name: String, done: u32, total: u32 },
    Done,
    Error { message: String },
}

#[tauri::command]
fn start_turn(prompt: String, on_event: tauri::ipc::Channel<TurnEvent>,
              state: tauri::State<'_, AppState>) -> Result<(), String> {
    let cancel = state.cancel.clone();              // Arc<AtomicBool>, same primitive as the TUI
    cancel.store(false, Ordering::SeqCst);
    let (tx, rx) = std::sync::mpsc::channel();      // core's existing event type
    std::thread::spawn(move || core_run_turn(prompt, tx, cancel)); // placeholder for the core entry point
    std::thread::spawn(move || {                    // forwarder: mpsc -> webview
        for ev in rx {
            if on_event.send(TurnEvent::from(ev)).is_err() { return; }
        }
        let _ = on_event.send(TurnEvent::Done);
    });
    Ok(())                                          // returns immediately; stream continues
}

#[tauri::command]
fn cancel_turn(state: tauri::State<'_, AppState>) { state.cancel.store(true, Ordering::SeqCst); }
```

```ts
import { invoke, Channel } from '@tauri-apps/api/core';
const ch = new Channel<TurnEvent>();
ch.onmessage = (e) => { if (e.type === 'delta') append(e.text); /* ... */ };
await invoke('start_turn', { prompt, onEvent: ch });   // camelCase arg <-> on_event
```

## 3. Capabilities, CSP, showing the report

Facts [V]: commands registered with `invoke_handler` need NO permission (allowed for every window) unless `build.rs` opts in via `tauri_build::AppManifest::new().commands(&[..])`. Every file in `capabilities/` is auto-enabled. Plugin commands are denied unless listed.

Minimal `capabilities/default.json`:

```json
{ "$schema": "../gen/schemas/desktop-schema.json", "identifier": "main", "windows": ["main"],
  "permissions": ["core:default", "core:window:allow-start-dragging"] }
```

- `allow-start-dragging` is only for `data-tauri-drag-region` with the overlay title bar [V].
- Open file/URL in the default browser: do it Rust-side inside our own command with `tauri_plugin_opener::OpenerExt` - `app.opener().open_url(url, None::<&str>)` / `open_path(path, None::<&str>)` [V]. Rust-side calls need no capability, so the webview gets zero opener permissions. Validate in the command (scheme is https, path is under the reports dir).
- Only if calling from JS instead: `opener:allow-open-url` (`opener:default` already allows http/https/mailto/tel + reveal-in-dir) and a scoped `{ "identifier": "opener:allow-open-path", "allow": [{ "path": "$HOME/.moneyball/reports/**" }] }` [V shape; that exact glob U].

CSP (`app.security.csp`; applied only if set; Tauri appends its own nonces/hashes at build time [V]):

```json
"csp": { "default-src": "'self'", "connect-src": "ipc: http://ipc.localhost",
         "img-src": "'self' data:", "style-src": "'self' 'unsafe-inline'",
         "object-src": "'none'", "base-uri": "'none'" },
"devCsp": null-or-looser (vite HMR needs ws://localhost:5173 in connect-src)
```

Report display. Verified in this repo: `report/template.html` has 0 `<script>` tags, one inline `<style>`, base64 images - so it needs no JS at all.

| Option | Needs | Verdict |
|---|---|---|
| `<iframe sandbox="" srcdoc={html}>` (html returned by a command) | `img-src data:`, `style-src 'unsafe-inline'` | RECOMMENDED. No extra protocol, no fs scope; `sandbox=""` gives an opaque origin with scripts off, so no path to IPC |
| asset protocol: `iframe src=convertFileSrc(path)` | `assetProtocol.enable` + `scope`, `frame-src asset: http://asset.localhost` | more surface (file-serving scope) for no gain; useful only if reports get huge |
| second `WebviewWindow` | still needs asset protocol or a custom protocol to load a file; own commands are callable from every window by default | heaviest; only if a detachable report window is a product requirement |

Caveats: srcdoc documents inherit the parent CSP (HTML spec) [M]. Tauri injects nonces into `style-src`, and browsers ignore `'unsafe-inline'` when a nonce is present, which would block the report's inline `<style>` [M - known gotcha]. Fix if hit: `"dangerousDisableAssetCspModification": ["style-src"]` [V option exists; the interaction itself U]. Multi-MB srcdoc strings over IPC: fine in principle, measure. "Open in browser" (opener, above) is the zero-risk fallback and already matches the CLI.

## 4. macOS specifics

Window chrome [V config ref]:
- `titleBarStyle`: `Visible` | `Transparent` | `Overlay`. Overlay = content under the title bar; needs your own drag region; drag does not work while the window is unfocused.
- `hiddenTitle: true`; `trafficLightPosition: {x, y}` (requires Overlay + `decorations: true`).
- `data-tauri-drag-region` applies only to the element it is on, not children [V].
- Vibrancy: `windowEffects: { effects: ["sidebar" | "underWindowBackground" | "hudWindow" | ...] }`, requires `transparent: true`; macOS 26 adds `liquidGlassRegular/Clear` [V]. Transparent windows on macOS need `app.macOSPrivateApi: true` + tauri feature `macos-private-api` [M] - fine for Developer ID, blocks App Store. Recommendation: v1 = Overlay + hiddenTitle + inset, no vibrancy.

```json
"windows": [{ "label": "main", "title": "Moneyball", "width": 1200, "height": 800, "minWidth": 900,
  "minHeight": 600, "titleBarStyle": "Overlay", "hiddenTitle": true, "trafficLightPosition": {"x": 16, "y": 18} }]
```

Menu [V menu guide]: on macOS every item must sit in a submenu and the first submenu becomes the app menu. Tauri installs a default menu (App/File/Edit/View/Window/Help) when none is set [M]. If a custom menu is built, keep the predefined Edit items (undo/redo/cut/copy/paste/select_all) or Cmd+C/V/A stop working in the webview [M].

Single instance: `tauri-plugin-single-instance` must be the FIRST plugin registered; callback `(app, args, cwd)`; focus `main` in it; no capability needed [V]. LaunchServices already dedupes Finder/Dock launches [M]; the plugin covers direct binary exec and `open -n`. Worth it here because two processes would write the same session JSONL files.

Lifecycle [M]: Tauri exits when the last window closes (not the Mac convention). Keep that for v1.

Launched from Finder (matters for moneyball-core):
- cwd is `/`. Core's `Config::resolve_optional` falls back to `current_dir()` for the workspace (`config.rs:228`, plus `:341/:364/:387`) [V repo]. The app MUST pass an explicit data root (or set `MONEYBALL_DATA_ROOT` before first core call) - never rely on cwd. Needs a workspace picker or a default such as `~/Moneyball` on first run.
- Env is launchd's: PATH is `/usr/bin:/bin:/usr/sbin:/sbin`, no shell dotfiles. `MB_AGENT`, `MONEYBALL_*`, `OPENAI_API_KEY`-style provider env keys will be ABSENT [V those are the vars core reads]. `~/.moneyball/auth.json` still works. Tauri docs point to `fix-path-env-rs` (git-only crate, not on crates.io [V]) - not needed unless we spawn external tools.
- `HOME` is set, so `~/.moneyball/` (auth, reports, global config) resolves [M].
- Writable paths: app is not sandboxed (Developer ID), so anything the user can write. No TCC prompt: `~/.moneyball`, `~/Library/Application Support/<bundle id>` (`app.path().app_data_dir()`), `~/Library/Logs/<bundle id>`, `~/Library/Caches/<bundle id>`. TCC prompt on first touch: `~/Documents`, `~/Desktop`, `~/Downloads`, removable/network volumes [M]. Never write inside the .app bundle (breaks the signature).

## 5. Signing and notarization

What the user must obtain (nothing here can be done by an agent):
1. Apple Developer Program membership, paid ($99/yr). Free accounts cannot notarize [V].
2. A **Developer ID Application** certificate (only the Account Holder can create it) [V]. Without Xcode: Keychain Access > Certificate Assistant > Request a Certificate from a CA (saves a CSR), upload at developer.apple.com > Certificates, download the `.cer`, double-click to install in the `login` keychain [V flow]. The private key stays in that keychain. Likely also needed with CLT only: Apple's "Developer ID - G2" intermediate from apple.com/certificateauthority (Xcode normally installs it) [M/U]. Success check: `security find-identity -v -p codesigning` lists `Developer ID Application: NAME (TEAMID)` (today: 0).
3. Team ID (10 chars, Membership page).
4. Notarization credentials, one of:
   - App Store Connect API key (RECOMMENDED: no 2FA, revocable): Users and Access > Integrations > team key, role Developer or higher [M role]. Gives Issuer ID, Key ID, `AuthKey_<KEYID>.p8` (downloadable once) [V].
   - Apple ID + app-specific password (account.apple.com) + Team ID [V].

Env vars Tauri reads [V env reference + bundler source `macos/sign.rs`]:

| Var | Meaning |
|---|---|
| `APPLE_SIGNING_IDENTITY` | overrides `bundle.macOS.signingIdentity`; e.g. `Developer ID Application: NAME (TEAMID)`; `-` = ad-hoc |
| `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD` | base64 `.p12` + its password; CI only (temp keychain). Not needed locally when the cert is in the login keychain |
| `APPLE_API_ISSUER`, `APPLE_API_KEY`, `APPLE_API_KEY_PATH` | API key auth. If the path is unset Tauri searches `./private_keys`, `~/private_keys`, `~/.private_keys`, `~/.appstoreconnect/private_keys` for `AuthKey_<KEY>.p8` (also `API_PRIVATE_KEYS_DIR`) |
| `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID` | Apple ID auth; checked FIRST, so do not set both sets. `APPLE_PASSWORD` accepts `@keychain:` / `@env:` refs |
| `APPLE_PROVIDER_SHORT_NAME` | only if the Apple ID is in several teams |

What `tauri build --bundles app,dmg` does [V source]: codesign inside-out (frameworks, sidecars, then the .app) with hardened runtime; `ditto` zip; `xcrun notarytool submit --wait`; `xcrun stapler staple` on the **.app**; build the DMG (`bundle_dmg.sh`: hdiutil + Finder AppleScript); codesign the DMG. If no notarization env is found it only logs "skipping app notarization" - a silent downgrade, so assert on the verification below. `--skip-stapling` exists [V].

GAP [V source]: the **DMG itself is signed but not notarized or stapled**. Add after the build:

```sh
xcrun notarytool submit "$DMG" --key "$APPLE_API_KEY_PATH" --key-id "$APPLE_API_KEY" \
  --issuer "$APPLE_API_ISSUER" --wait
xcrun stapler staple "$DMG"
```

Hardened runtime / entitlements: `bundle.macOS.hardenedRuntime` defaults to `true` [V]; notarization requires it. Entitlements go in a plist referenced by `bundle.macOS.entitlements` and are applied at sign time [V]. For this app (no sandbox, no camera/mic, no dylib loading, outbound HTTPS only): start with NO entitlements file. WebKit's JIT runs in Apple's own WebContent process, so `com.apple.security.cs.allow-jit` should not be needed [M/U - community guides add it and `allow-unsigned-executable-memory` by reflex; one Qt doc claims it is required on arm64]. Test: notarized build with no entitlements, launch, load UI. Add `allow-jit` only if that fails. `com.apple.security.network.client` is a sandbox entitlement - irrelevant here. Also set `bundle.macOS.minimumSystemVersion` (default `10.13` [V]; pick e.g. `"12.0"`) and a stable `identifier` (reverse-DNS; it names the data dirs and is baked into the signature).

Command Line Tools only [V on this machine]: `xcrun --find notarytool` and `stapler` resolve to `/Library/Developer/CommandLineTools/usr/bin/`; `codesign`, `hdiutil`, `ditto`, `spctl`, `osascript`, `SetFile` are in `/usr/bin` or `/usr/sbin`. Full Xcode is NOT required. `altool` is absent and not used by Tauri 2. Not verified end to end (no identity on this machine yet) [U].

DMG [V docs + source]: config under `bundle.macOS.dmg` (`background`, `windowSize` default 660x400, `appPosition`, `applicationFolderPosition`). The script drives Finder via `osascript`: needs a GUI session and Automation permission for the terminal (error -1743 otherwise; System Settings > Privacy & Security > Automation). With `CI=true` Tauri passes `--skip-jenkins`: the DMG still builds but icon layout is not applied; `TAURI_BUNDLER_DMG_IGNORE_CI=true` forces the Finder step. An agent shell may trigger that permission prompt on first run.

Verify (run all; expected output in comments):

```sh
codesign --verify --deep --strict --verbose=2 Moneyball.app        # valid on disk / satisfies its Designated Requirement
codesign -dv --verbose=4 Moneyball.app 2>&1 | grep -E 'Authority|TeamIdentifier|flags'  # Developer ID Application..., flags=0x10000(runtime)
codesign -d --entitlements - Moneyball.app                          # what was actually granted
spctl -a -vvv -t exec Moneyball.app                                 # accepted, source=Notarized Developer ID
spctl -a -vvv -t open --context context:primary-signature Moneyball_x.y.z_aarch64.dmg   # accepted, Notarized Developer ID
xcrun stapler validate Moneyball.app && xcrun stapler validate Moneyball_x.y.z_aarch64.dmg
xcrun notarytool log <submission-id> --key ... --key-id ... --issuer ...   # on rejection: per-file reasons
```

Real-user test: download the DMG through a browser (sets the quarantine xattr) on another Mac or a fresh user account, mount, drag to Applications, double-click - no Gatekeeper warning.

## 6. End to end testing from an agent on macOS

`tauri-driver` (2.1.0) used directly: Windows and Linux only - "macOS has no WKWebView driver tool" [V]. Real options, in recommended order:

1. **Playwright + mocked IPC in a browser (fast loop).** Serve `ui/` with vite, open in Playwright (use the `webkit` project for closest rendering; it is not the system WKWebView), install mocks with `@tauri-apps/api/mocks`: `mockIPC((cmd, args) => ...)`, `mockWindows('main')`, `clearMocks()`; `mockIPC(fn, { shouldMockEvents: true })` for `listen/emit` (since 2.7.0, partial: no `emitTo`) [V]. Channels: not documented, but mocks.ts registers `transformCallback`, so `new Channel()` works and the handler can drive the stream with `args.onEvent.onmessage({type:'delta',...})` [V by reading source; U in practice]. Covers UI states, screenshots, pixel checks. Does not cover Rust, real WKWebView quirks, window chrome, CSP.
2. **WebdriverIO `@wdio/tauri-service` 1.5.1 with the embedded provider (real app, real WKWebView).** Now the path the official Tauri docs recommend: "works on Windows, Linux, and macOS", no external driver [V docs]. Needs crates `tauri-plugin-wdio` + `tauri-plugin-wdio-webdriver` (both 1.5.1 [V]), npm `@wdio/tauri-plugin` imported in the frontend entry, `app.withGlobalTauri: true`, permissions `wdio:default` + `wdio-webdriver:default`, default port 4445. Test-only: gate behind a cargo feature / `cfg(debug_assertions)` and a separate capability file so nothing ships in the release DMG [V docs]. Not run here [U]; `withGlobalTauri` and the extra capability must not leak to release.
3. **Screenshot the real window.** `screencapture -x -l <CGWindowID> out.png` (or `-R x,y,w,h`); needs Screen Recording permission for the terminal, and the window id needs a small CoreGraphics lookup (swift/JXA) [M]. UI scripting (clicks, menu) via `osascript` System Events needs Accessibility permission [M]. Good for chrome/traffic-light/vibrancy pixel checks that options 1-2 cannot see. Both permissions are one-time user grants.
4. **Rust-level command tests**: tauri feature `test` - `tauri::test::mock_builder()`, `mock_context(noop_assets())`, `get_ipc_response` - exercises commands without a webview [M]. Most of this value is already covered by testing moneyball-core directly.
5. Others: `tauri-plugin-webdriver` 0.2.4 (community embedded WebDriver, exists on crates.io [V], untested [U]); CrabNebula's tauri-driver fork (macOS needs a paid API key [V]); Safari Web Inspector attaches to debug builds for manual inspection [M]. Release builds have no devtools unless the `devtools` feature is on [M].

Suggested stack: option 1 for every UI change, option 2 as a handful of smoke tests (launch, run one turn against a fixture, open report), option 3 for a final visual pass on the signed build.
