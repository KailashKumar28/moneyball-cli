# Review: branch `desktop` against `master`

Read-only review of `git diff master...HEAD` (plans/, lockfiles, fixture JSON and icons skipped).
Verified by reading the code; `cargo test --workspace` was run and is green. `pnpm check` and the
real-app e2e run were NOT run, so nothing below was reproduced in the running app.

Counts: 1 must-fix, 9 should-fix, 5 nits. Paths are relative to the repo root; `desktop/` means
`crates/moneyball-desktop/`.

---

## Must-fix

### 1. A workspace pick that cannot be remembered leaves the UI on workspace A and Rust on workspace B
`desktop/src/workspace.rs:80-83`, `desktop/ui/src/App.tsx:29-37,50-58`

`workspace_pick` calls `open(&state, &dir)?` (which swaps `AppState.workspace` to B and drops the
session), then `workspace::remember(&dir)?`. The comment above that line says "The workspace is
open either way; only next launch forgets it", but the `?` turns a remember failure into a
rejected command.

Sequence: workspace A is open; `~/.moneyball/config.json` is unparsable or not a JSON object
(`write_last` refuses to overwrite it, `core/src/workspace.rs:60-73`), or the picked path is not
UTF-8. The user presses Cmd+O and picks B. Rust state is now B. The UI gets a rejection, so
`picked` stays A, and it shows the error screen with "Back to A". Clicking it re-shows the Shell
for A (same React key, no remount). Every command now answers for B under A's name: Today, Brief
and Funnel show B's figures, Refresh pulls B, the advisor reads B.

Fix: do not fail the command on a remember error. Return `Ok(Some(shown))` and drop or surface the
remember error separately (for example `let _ = workspace::remember(&dir);`, or call `remember`
before `open` if a failure should really refuse the pick).

## Should-fix

### 2. The open workspace's config is read once and never again, so the app's own Terminal fixes do not take effect
`desktop/src/state.rs:32-36`, `desktop/src/workspace.rs:46-60`, `desktop/src/turn.rs:156-170`, `desktop/ui/src/App.tsx:24`

`AppState.workspace` holds the `AppConfig` (with its parsed `WorkspaceConfig`) from the moment
`workspace_current` or `workspace_pick` ran. `workspace_current` is called only when the webview
mounts; `today` on window focus re-reads data but not the config.

Sequence: a workspace has no model. The advisor refuses with `no_model` and the fix
"In Terminal: moneyball, then its setup". The user does exactly that, comes back and sends the
message again. `turn_start` clones the cached config, `model_configured` fails again, same
refusal, until the app is relaunched or the same folder is re-picked. The same holds for
products added in setup (the Funnel product list comes from the `Workspace` returned at mount),
goals, brand and `target_rs_per_q`.

Fix: re-open the config where it is cheap and natural: make `AppState::workspace()` return
`workspace::open(&data_root, None)` (a small file read) with the cached one as fallback, or
re-open inside `today` (already called on focus) and have the UI re-read `Workspace` then.

### 3. The refresh state is one global slot that outlives its workspace and its run
`desktop/src/state.rs:41-52`, `desktop/src/refresh.rs:86-105,150-156`, `desktop/ui/src/useRefresh.ts:58-78`

`state_view` prefers the in-memory `RefreshRun` whenever `run.steps` is non-empty and falls back
to `runs::latest` only before the first run of the launch. `AppState::open` never resets
`refresh`. Three wrong results follow:

- Run a refresh in workspace A, then open workspace B. The Shell remounts, `useRefresh` calls
  `refresh_state`, and B's Refresh screen shows "Last refresh, <A's day>" with A's step counts.
- A refresh that could not start (the schedule or a terminal refresh holds the lock) leaves
  `steps = all_waiting()`, `running = false`. From then on `refresh_state` returns four blank
  steps under "Last refresh, <day>" instead of the recorded run, for the rest of the launch.
- After any in-app run, a later scheduled or terminal run never shows on the Refresh screen.

Fix: in `refresh_state`, use the in-memory run only while `run.running`; otherwise return
`runs::latest(&cfg)` (core writes the record before `Finished`, and a died run's record "keeps the
steps that finished"). That removes the need to reset anything on a workspace change.

### 4. "Month to date" asks for up to 31 days from a snapshot that holds 28
`desktop/src/report.rs:62-73` (`month_to_date`), `desktop/ui/src/screens/Report.tsx:24`, `desktop/src/refresh.rs:191-196` (`days: 28`), `core/src/report/mod.rs:51`

`ReportDay.month_to_date` is the data day's day-of-month (1 to 31) and the UI passes it as `days`.
A refresh pulls 28 days and `report::build` does not clamp (`d0 = d1 - (window_days - 1)`).
`funnel.rs:31-32` clamps to 28 for exactly this reason.

Sequence: the data day is the 29th, 30th or 31st. The user picks "Month to date" and Generate. The
report's window says it starts on the 1st, but the snapshot has no rows for the first 1 to 3 days,
so spend and leads are silently short while labelled month to date.

Fix: cap in `report_days_of` (`.min(28)`) and word the option accordingly, or refuse with a
sentence when `month_to_date > 28`; or pull 31 days in the desktop refresh.

### 5. The "Generate report" action generates whatever the Report screen last had selected, and Today is not re-read afterwards
`desktop/ui/src/App.tsx:86-95`, `desktop/ui/src/screens/Report.tsx:23-32`

`onAction` for `kind: "report"` calls `report.current?.generate()`, which is the screen's `run`
closure over its own `shown` date and `win`.

Sequence: the user earlier chose 02 Oct and "7 days" on Report. Today's refresh ends with
"No report was written" and its "Generate report" button (core's `/report`, meaning the day's
daily report). Clicking it writes a 7-day report for 02 Oct (range-suffixed file), not the daily
report for the day just refreshed. Separately, even with default selections, nothing bumps
`version` after a successful generate, so Today keeps saying "no daily report for this day yet"
until the window loses and regains focus.

Fix: have the action call `reportGenerate({ days: 1 })` with no date (and reset the screen's
`date`/`win`), and call the same `setVersion` bump that a settled refresh uses when a generate
succeeds.

### 6. The desktop still tells the user, on screen, to type a slash command
`desktop/src/action.rs:55-60,100-109`, pinned by `desktop/src/action_tests.rs:116-119`

AGENTS.md: "Do NOT let the desktop tell a user (on screen or through the advisor) to type a slash
command". `inside_moneyball` builds `does = "then type /setup meta there - ..."`, and the default
branch does the same for any other slash command core may name.

Sequence: the Meta token expires. The refresh's meta step carries `fix: "/setup meta"`. The
Refresh screen and Today show "In Terminal `moneyball`, then type /setup meta there". `say()`
already avoids this for the model ("`moneyball` in Terminal, then its Meta setup").

Fix: word `inside_moneyball` the way `say` does ("then open its Meta setup"), or add a
`moneyball setup [meta]` sub-command and translate to it; if the current wording is intended,
amend the AGENTS.md rule to exempt steps typed inside the terminal app.

### 7. Sessions written by the TUI are listed and reopened in the desktop, slash commands included
`desktop/src/session.rs:66-80,84-88`, `core/src/config.rs:253-255`

Both front-ends use `cfg.sessions_root()` (the workspace), and `sessions_list` returns every file.

Sequence: the user ran `/brief` and `/funnel Namma Mane` in the TUI. In the app the session list
shows the preview "/brief"; opening it shows the user rows "/brief", tool outputs that say
"Fix: /connect crm (moneyball connect crm in a shell)" and assistant text citing `/funnel ...`.
The next `turn_start` sends that whole history to the model next to a system prompt that says
"slash commands: none", so the model has slash commands in context to repeat. Also, the same
file can be appended by a TUI (`--continue`) and the app at once; single-instance only guards
app against app.

Fix: smallest is to record the front-end in the session header (additive field) and have
`sessions_list` leave out sessions another front-end wrote; otherwise filter out sessions whose
first user item starts with `/`.

### 8. The desktop advisor is told the Brief screen "self-heals", which it does not
`core/src/agent/prompt.rs:102-110`, `core/src/agent/exec.rs:32-39`, `desktop/src/action.rs:78`

With no snapshot the state block reads "snapshot: none yet. the Brief screen self-heals by
running the Refresh button when a token is configured", and every tool answers "tell the user to
run the Refresh button (or the Brief screen, which self-heals)". The desktop `brief` command only
loads (`desktop/src/brief.rs:60-67`); self-heal is the TUI's `/brief`.

Sequence: first run, no data. The user asks the advisor anything; a tool reports no snapshot; the
model tells the user to open the Brief screen and wait. Nothing happens. That is the dead end
CLAUDE.md warns about.

Fix: make the self-heal clause the front-end's to give, for example only emit it when
`say("/brief") == "/brief"`, or add a `FrontEnd` flag; the desktop sentence then names Refresh
only.

### 9. plans/desktop/IPC.md no longer describes what is sent
`plans/desktop/IPC.md:27-30,45,48-51,72,75,80,83,99`

ARCHITECTURE.md 5b says the contract is pinned and IPC.md "names every command and shape"; IPC.md
itself says "do not drift". `ui/src/ipc/types.ts:1-4` and `ui/NOTES.md` admit the differences
but the document was not updated:

- `Action.refresh` has `force: boolean` (`action.rs:17-21`).
- `StepView.status` is `done | partial | failed | skipped | waiting | running`, not `ok | ...`.
- `report_days` returns `ReportDay[]` (`date`, `day`, `month_to_date`), not `string[]`.
- Day numbers carry `source?: "meta" | "crm"`.
- `session_current` does not create a session; `SessionSnapshot.id` is null until the first turn.
- `turn_start` also rejects with kind `empty`; `workspace_pick` with `busy`; `refresh_start`'s
  `force` reaches core.

Fix: update IPC.md to the shapes in `types.ts` (which the fixtures pin).

### 10. The UI composes product sentences, one of them a reworded core constant
`desktop/ui/src/lib.tsx:103-109`, `desktop/ui/src/screens/Funnel.tsx:77`, `desktop/ui/src/screens/Brief.tsx:30,65-69`, `desktop/ui/src/screens/Today.tsx:51`

AGENTS.md and IPC.md: "The UI never composes product wording".

- `StepDetail` writes "from today's earlier pull" in TypeScript while core has `REUSED_NOTE`
  ("from today's earlier pull (--force pulls Meta again)", `core/src/refresh/show.rs:9`). Two

- Funnel: "Verdicts withheld. This snapshot has no CRM data: qualified is unknown, not zero. Fix

- Brief: "CRM columns hidden.", "Meta, CRM and Qual. are leads over the 7 days. Gap is qualified

Fix: add the sentences to the Rust views (`StepView.note`, `FunnelView.notes` only,

## Nits

### 11. Get-or-create of the session slot is not atomic
`desktop/src/session.rs:43-52,55-62,66-80`, `desktop/src/turn.rs:209-214`

`current_or_new` reads the slot, then creates and sets it under a second lock; `idle` checks and
`set_session` replaces under separate locks. Two `turn_start` calls landing together (they are
`async` commands on the pool) can each create a session and run two turns at once, the one-turn
guard being per session; a `session_open` between `current_or_new` and `start_turn` orphans a
running turn. The UI's `active` flag makes this unlikely today. Fix: do check-and-set inside one
`lock(&self.session)` (an `AppState::session_or_insert_with`, and `replace_if_idle`).

### 12. A finished refresh's verdict, fixes and numbers live only in the webview
`desktop/ui/src/useRefresh.ts:22,105-108`, `desktop/src/refresh.rs:36-42`

5b: "The webview holds nothing it cannot re-read after a reload." `RefreshState` carries steps
only, so after a reload the verdict sentence, the fix actions, the rerun and the day's numbers of
the run just finished are gone (the steps table does not render `step.fix`). The same goes for a
turn that ends in `failed` while the window is reloading: the snapshot has no item for it, so the
poll ends silently. Fix: keep the last `Finished` in `RefreshRun` and return it from
`refresh_state`.

### 13. The same logic or sentence in two places
- `desktop/src/turn.rs:173-185` `model_configured` re-implements `core/src/agent/driver.rs:209-222`
  `model_for`; if core's rule changes the desktop refuses turns core would start. Export one
  check from core.
- "stopped at step N" is built in `desktop/src/run_view.rs:126-132` and in
  `crates/moneyball-tui/src/refresh_cell/mod.rs:96`; "cheapest Meta lead first: " in
  `desktop/src/brief.rs:52` and `core/src/agent/tool_text.rs:52`. AGENTS.md puts anything both
  front-ends say in core (`refresh::gaps` could cover the failed outcome).

### 14. Dead code in the UI
`desktop/ui/src/lib.tsx:69-76`: `dayLabel` (and `DAYS`) has no caller in `ui/` or `e2e/`, and it
is date wording computed in the UI, which the contract forbids anyway. Delete it.

### 15. Copy reports success when pbcopy fails
`desktop/src/clipboard.rs:13-20`: `child.wait()?` ignores the exit status, so a non-zero pbcopy
exit still resolves and the button says "Copied". Fix: `if !child.wait()?.success() { return Err(..) }`.

## Checked and found sound

- Lock ordering: `AppState::open` takes workspace, then session slot, then the session; no other
  path nests them in another order, and no lock is held across a channel send or a thread spawn
  except `start_turn` (short). `state::lock` survives poisoning.
- Turn forwarder: every event is applied to the session before it is sent; a final event clears
  `turn_active` before the UI hears it; a closed channel calls `stream_closed` and emits `died`
  once; a gone webview stops sends but the turn still records. Delta coalescing flushes before
  every non-delta event and on timeout. Cancel after completion is reset by the next `start_turn`.
- Refresh forwarder: `running` is false before the last event is sent; `could_not_start` is
  final (no `died` after); a second start is refused under the lock.
- Refresh against report generate on one file: core writes temp-then-rename with a per-writer
  temp name (`core/src/report/mod.rs:263-267`), so the desktop `busy` guard is extra, not
  load-bearing. Multi-day reports get range-suffixed names and never overwrite the daily one.
- Workspace switch mid-turn: the old session is interrupted and its forwarder finishes the file;
  the Shell remounts by key so late events hit dead callbacks only. Workspace pick is refused
  while a refresh runs.
- Single instance: the plugin is registered first and focuses the existing window.
- `report_open_in_browser`: both sides canonicalized (symlinks and `..` resolved), must be a
  regular `.html` file under `<workspace>/.moneyball/reports`; `report_for`/`report_generate`
  dates must parse as YYYY-MM-DD; `session_open` ids are restricted to `[A-Za-z0-9-]`.
- CSP and capabilities: `default-src 'self'`, `connect-src` IPC only, no remote images, no plugin
  permission granted to the page (opener, dialog and clipboard are called from Rust), wdio
  plugins and their capability exist only behind the `e2e` feature and e2e config; the release
  script builds without it.
- Report iframe: `sandbox=""` with `srcDoc`; no scripts, no same-origin.
- Markdown: `disableParsingRawHTML`, links rendered as inert spans, images dropped; covered by
  `ui/tests/behaviour.spec.ts:107`. No model text reaches the clipboard.
- Secrets: the Meta token is read at the edge and passed to core only; no command returns
  `auth.json` content; `AppError` carries `kind`, `reason`, `fix` only.
- No-CRM is null: `brief/wire.rs` and `funnel/wire.rs` null every CRM-derived field, with tests;
  the UI's `num`/`rupees`/`pct` render null as an empty cell and hide CRM columns.
- A message starting with `/` is refused before any session or model call; the desktop
  `FrontEnd` has no commands and `say` never returns a slash command (tested over core's list).
- TUI/CLI extraction: `crates/moneyball` and `core/src/config.rs` are untouched (resolution order
  unchanged; `last_workspace` is read only by the desktop). Turn start, cancel, persist, replay,
  the landing words, the refresh verdict, `CrmHealth::note` and the tool texts were compared
  with the removed TUI code and read the same; the removed TUI tests have counterparts in core
  (`landing/tests.rs`, `refresh/finish.rs`, `agent/driver_tests.rs`, `agent/exec_tests.rs`,
  `crm/status_tests.rs`). The one intended wording change is the singular in `counts_detail`
  ("1 page"), safe for every key it lists.
- Rust IPC types against `ui/src/ipc/types.ts`: field names, tags and nullability match for
  every command and event read.
